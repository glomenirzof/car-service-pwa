# Новая студия за 6 минут

Новая студия — это папка `tenants/<slug>/` (один `business.json` + картинки).
Код, сборка, Supabase-проект и функции общие; прежние студии не затрагиваются:
сборка рендерит **все** папки `tenants/*`, а публикация в БД меняет только свою студию.

Предполагается, что платформа уже развёрнута по [SETUP.md](SETUP.md) и у вас есть
`DATABASE_URL` (и для приглашения владельца — `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`).

## Подготовьте заранее

- Название, короткое название (до 12 символов), телефон, адрес, часовой пояс.
- Акцентный цвет `#RRGGBB` (контраст с тёмным фоном ≥ 3:1 — проверяется автоматически).
- Посты/боксы и что они умеют (`capabilities`), услуги с длительностью, буфером и ценой.
- Картинки: квадратная иконка PNG ≥ 512×512, логотип SVG, hero ≥ 1200 px по ширине,
  фото галереи ≥ 800 px. Форматы jpg/png/webp. Webp-версии, иконки maskable,
  apple-touch-icon и 15 стартовых экранов iOS генерируются сами.

## Шаги

| # | Действие | Команда | Замер* |
|---|---|---|---|
| 1 | Создать папку из шаблона или похожей студии | `npm run tenant:new -- volna --name "Волна Детейлинг" --from graphite --accent "#4EC3F2" --timezone Europe/Kaliningrad` | 1 с |
| 2 | Заполнить `business.json`: тексты, контакты, часы, посты, услуги | редактор | ~2–3 мин |
| 3 | Заменить файлы в `tenants/volna/images/` (имена как в `brand`/`gallery`) | файловый менеджер | ~1 мин |
| 4 | Проверить | `npm run tenant:validate -- volna` | 1 с |
| 5 | Опубликовать в БД (статус preview) | `npm run tenant:publish -- volna` | < 1 с |
| 6 | Собрать и задеплоить статику | `git add tenants/volna && git commit && git push` (Cloudflare Pages соберёт) или `npm run build && npx wrangler pages deploy dist` | сборка 22 с + деплой |
| 7 | Выдать доступ владельцу | `npm run owner:invite -- --tenant volna --email owner@volna.example` | секунды |
| 8 | Проверить опубликованное | `npm run tenant:verify -- volna --url https://<домен> --api https://<ref>.supabase.co/functions/v1` | 2 с |
| 9 | Включить Live | `npm run tenant:publish -- volna --live` | < 1 с |

\* Замеры — реальный прогон шагов 1, 4, 5, 6 (сборка), 8 (`--dist`), 9 на локальной БД
с тремя студиями (см. ACCEPTANCE.md, раздел «Клонирование»). Шаг 7 требует hosted Supabase Auth
и локально заменялся на `scripts/dev-owner-session.ts`; шаги с доменом и деплоем в этой
среде не выполнялись.

Ссылки студии после деплоя:

- клиенты: `https://<домен>/s/volna/` (устанавливается как отдельное приложение со своей иконкой);
- владелец: `https://<домен>/s/volna/owner/`.

## Что проверяется автоматически

`tenant:validate` — схема `business.json`, существование и размеры картинок, квадратность
иконок, контраст акцента, что у каждой услуги есть подходящий пост. Предупреждает, если
у клона остались название/телефон/адрес/описание другой студии.

`tenant:publish` — атомарно в одной транзакции: услуги/посты/часы/исключения; меняются
только данные этой студии. Выводит, что сохранено (записи, фото владельца, его исключения).
Изменение цены не трогает уже созданные записи (цена фиксируется в записи).

`tenant:publish --live` — откажет с понятным списком, если нет владельца, часов,
телефона, адреса или бронируемой услуги (код выхода 1). При включении удаляет демо-записи
и включает настоящие уведомления.

`tenant:verify` — сверяет **опубликованное**, а не конфиг: хэш версии в БД, статус,
наличие свободного времени у услуг, что `anon` не читает таблицы; оболочку, manifest
(id/start_url/scope), иконки и splash в `dist/`; с `--url`/`--api` — живой сайт, глубокую
ссылку, заголовок `sw.js` и публичный API.

## Preview → Live

В preview студия работает полностью, но записи помечаются демо, а уведомления не
отправляются (задачи outbox получают статус `suppressed`). Можно показать владельцу
кабинет и пройти запись. После `--live` демо-записи удаляются; настоящие записи,
загруженные владельцем фото и его правки графика сохраняются при любых следующих
публикациях конфига.

## Если что-то пошло не так

- `tenant:validate` пишет ошибку по-русски с именем файла или поля — исправьте и повторите.
- Неправильно опубликовали: исправьте `business.json` и опубликуйте снова — публикация идемпотентна.
  Удалённая из конфига услуга не удаляется, а деактивируется (записи на неё остаются).
- Студию нужно временно скрыть: `update app.tenants set status = 'suspended' where slug = 'volna';`
  (вернуть — `tenant:publish -- volna --live`). Клиенты увидят «Студия временно не принимает
  записи онлайн», данные сохранятся.
